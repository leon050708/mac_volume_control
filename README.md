# 音量

macOS 原生的进程音量控制原型，使用 SwiftUI + Core Audio Process Tap。
要求 macOS 14.2+；本项目的构建目标为本机 CPU 架构，无第三方依赖。

## 构建与启动

需要安装 Apple Command Line Tools：

```sh
bash scripts/build.sh
open build/音量.app
```

1. 启动后点击 macOS 顶部菜单栏的三个滑杆图标，打开音量面板。应用不显示 Dock 图标。
2. 在其他应用播放音频；列表每秒刷新一次。
3. 开启对应进程右侧的开关，首次使用时允许系统音频录制。
4. 调节滑块，范围为 0–100%（线性幅度增益，50% 约为 −6 dB）。
5. 点击面板外部收起面板，音量控制继续运行。关闭开关，或通过齿轮菜单选择“全部恢复”“退出音量”，即可恢复进程的原始声音。

菜单栏面板只显示应用图标、名称、控制开关和音量。齿轮菜单中可打开“显示空闲进程”；进程 PID 放在名称的悬停信息中。操作成功时不显示提示，出错时仅出现可点击的错误图标。

## 可选自动启动

在面板右上角齿轮菜单中勾选“登录时自动启动”，即可在登录 macOS 后启动菜单栏应用；取消勾选即可关闭。默认不主动注册。使用 Apple 的 `SMAppService.mainApp`，开关反映实际系统状态；若 macOS 要求批准，可通过“在系统设置中允许…”前往登录项设置，也可取消待批准的注册。

自动启动只负责启动应用，不自动恢复进程的音频接管。开启前请将应用放在计划长期保留的位置；启用后不要删除或移动应用包。

若曾拒绝权限，请在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”检查本应用权限，随后退出并重新打开。
不同 macOS 版本的权限名称可能略有差异。构建脚本使用本地临时签名，重新编译后可能需要重新授权；正式分发应改用稳定的开发者签名。

## 实现

每个被控制的进程建立一条独立音频链路：

```text
Core Audio 进程对象
    → 指向默认输出设备 stream 0 的 Process Tap
    → 私有 Aggregate Device（Tap 输入 + 原输出设备）
    → 同一个 HAL IOProc 中对 Float32 PCM 乘以增益
    → 原输出设备
```

- `kAudioHardwarePropertyProcessObjectList` 枚举接入 Core Audio 的进程；PID 只用于显示和验证身份。
- `CATapDescription(processes:deviceUID:stream:)` 选择进程和输出流，避免立体声 mixdown 的额外声道折叠。
- `.mutedWhenTapped` 仅在读取 Tap 期间静音原始路径，避免重复播放；停止读取后恢复原声音。
- 默认输出设备作为聚合设备的主时钟，Tap 启用漂移补偿。
- 实时回调全部用 C 实现，不分配内存、不调用 Swift、不加锁；主线程通过无锁原子变量传递增益。
- 音量变化使用约 5 ms 的满量程渐变，降低突变带来的点击声。
- 进程退出、输出设备或采样格式变化、缓冲布局异常时，界面定时检查会停止对应链路。
- 音频只在内存中实时处理，不写文件或上传。
- `MenuBarExtra` 的窗口样式提供菜单栏弹出面板；`LSUIElement` 隐藏 Dock 图标。音频模型由应用持有，收起面板不停止控制。

## 第一版边界

- 按进程控制，暂未把浏览器、Electron 等应用的多个辅助进程合并到同一滑块；进程重启后需重新开启。
- 只接管开启控制时默认输出设备的第一个输出流。支持单流、单声道／立体声、Float32 PCM；其他格式明确报错。
- 尝试禁用物理设备的输入声道，并校验聚合输入仅包含 Tap。不支持含额外输入的聚合布局。
- 切换输出设备后恢复原始输出，需重新开启控制；目前没有自动无缝迁移。
- 这是捕获、处理和重放链路，会增加缓冲延迟，不是系统原生的进程音量属性。
- 不承诺支持 DRM／受保护音频、独占设备输出、环绕声或所有蓝牙设备模式。
- 系统授权被拒绝时，部分系统可能返回静音数据而非明确错误；开关开启不等于已验证捕获成功。此时关闭开关恢复声音，再检查权限。
- 收起面板不等于退出应用；使用齿轮菜单中的“全部恢复”或“退出音量”停止控制。

## 验证

```sh
bash scripts/test.sh
build/音量.app/Contents/MacOS/ProcessVolume --list
```

C 测试包含实际 PCM 数值、交错／非交错声道映射、单声道转换、静音渐变和错误缓冲的越界保护，并开启 AddressSanitizer / UndefinedBehaviorSanitizer。
`--list` 只枚举进程，不启动音频捕获。

端到端人工验收：授权后，让两个不同进程同时播放；将其中一个调至 0%，确认另一个不受影响；恢复 100%，关闭控制；再检查退出应用、进程退出以及切换耳机时能恢复声音。自动化 DSP 测试不能替代这些实际音频设备检查。

参考：[Apple Core Audio Tap 示例](https://developer.apple.com/documentation/CoreAudio/capturing-system-audio-with-core-audio-taps)。
